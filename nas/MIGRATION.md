# แผนย้ายระบบทั้งหมดไปรันบน NAS (ระดับ 2)

> สถานะ: **แผน — ยังไม่ลงมือ** รอเจ้าของร้านเคาะหลังอ่านข้อดี/ข้อเสีย

## ภาพรวม

```
ปัจจุบัน                            หลังย้าย
─────────                           ─────────
มือถือพนักงาน                       มือถือพนักงาน
   │ https                             │ https (ต้องมี DDNS + SSL)
   ▼                                   ▼
GitHub Pages (หน้าเว็บ)             GitHub Pages (เหมือนเดิม) หรือย้ายลง NAS ด้วย
   │                                   │
   ▼                                   ▼
Supabase Cloud                      NAS (Docker: Supabase self-host)
 ├ Postgres (ข้อมูล)                 ├ Postgres (ข้อมูล) ← อยู่บ้านเรา
 ├ REST API + RLS                    ├ REST API + RLS
 ├ Edge Fn: line-order               ├ Edge Fn รันใน container
 ├ Edge Fn: order-reminders (cron)   ├ cron ของ NAS ยิงแทน
 └ ส่ง LINE                          └ ส่ง LINE (NAS ต้องออกเน็ตได้)
```

## เงื่อนไขที่ต้องมีก่อน (ขาดข้อใดข้อหนึ่ง = ยังย้ายไม่ได้)

1. **NAS รัน Docker Compose ได้** และ RAM ว่าง ≥ 4GB (Supabase self-host มี ~10 containers)
2. **เข้าจากนอกบ้านได้**: พนักงาน 2 สาขาต้องนับสต็อกจากมือถือที่ร้าน
   → ต้องมี DDNS (เช่น Synology QuickConnect ใช้ไม่ได้กับ API — ต้อง DDNS จริง) + เปิดพอร์ต + ใบรับรอง SSL (Let's Encrypt)
3. **ไฟ/เน็ตบ้านที่วาง NAS ต้องนิ่ง**: NAS ดับ = ทั้ง 2 สาขานับสต็อก/สั่งของไม่ได้ทันที
4. **มีคนดูแล**: อัปเดต, ดู log, กู้คืนเมื่อพัง — Supabase cloud ทำให้ฟรีอยู่ตอนนี้

## ข้อดี / ข้อเสีย

| | อยู่ Supabase (ปัจจุบัน) | ย้ายลง NAS |
|---|---|---|
| ข้อมูลอยู่กับใคร | cloud (สิงคโปร์) | อยู่บ้านเราเอง ✓ |
| ค่าใช้จ่าย | ฟรี (free tier) | ฟรี (ค่าไฟ+เน็ต) |
| ความเสถียร | สูง (SLA cloud) | ตามไฟ/เน็ตบ้าน ✗ |
| เข้าจากร้านได้ | ได้เสมอ | ต้องตั้ง DDNS+SSL เอง |
| LINE แจ้งเตือน cron | ทำงานอยู่แล้ว | ต้องย้าย+ทดสอบใหม่ |
| คนดูแล | ไม่ต้อง | ต้องมี ✗ |
| Downtime ตอนย้าย | — | ~ครึ่งวัน + ช่วงทดสอบ |

## ขั้นตอน (เมื่อเคาะแล้ว)

- **เฟส 0** — ทำระดับ 1 (backup ลง NAS) ให้รันนิ่ง ๆ ก่อน 1 สัปดาห์ → ได้ dump ที่พร้อมใช้เป็นตัวตั้งต้น
- **เฟส 1** — ตั้ง Supabase self-host บน NAS (docker compose ทางการของ Supabase), restore dump ลงไป, ตั้ง GRANT/RLS ให้ครบ (โปรเจกต์นี้เคย revoke default — สำคัญมาก)
- **เฟส 2** — แก้แอป: ย้ายค่า `SUPABASE_URL`/`ANON_KEY` เป็น config เปลี่ยนได้ (มีปุ่มสลับ cloud ⇄ NAS ไว้ถอยกลับ)
- **เฟส 3** — ย้าย Edge Functions (`line-order`, `order-reminders`, `sync-line-groups`, `admin-reset-password`) มารันบน NAS + ตั้ง cron ของ NAS ยิง order-reminders ทุก 15 นาที
- **เฟส 4** — ทดลองคู่ขนาน: beta.html ชี้ NAS / index.html ชี้ cloud → ใช้จริง 1-2 สัปดาห์
- **เฟส 5** — ตัดยอด: เลือกวันหยุด, sync ข้อมูลรอบสุดท้าย, ชี้ production เข้า NAS, เก็บ Supabase cloud ไว้เป็น fallback 1 เดือนแล้วค่อยปิด

## คำแนะนำ

ทำ**ระดับ 1 ก่อนเสมอ** — ได้ "ข้อมูลทั้งหมดอยู่บน NAS ทุกวัน" ทันทีโดยไม่เสี่ยงอะไรเลย
ส่วนระดับ 2 ให้ตอบคำถาม 4 ข้อในหัวข้อ "เงื่อนไข" ให้ครบก่อนค่อยเริ่ม
